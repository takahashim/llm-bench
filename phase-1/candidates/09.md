# コンテナ向けデプロイツールMRSKを試してみる

## 一行まとめ

MRSKは「コンテナ時代のCapistrano（Capistrano for Containers）」的なデプロイツールで、すごくDHHぽいです。これを使うと$5くらいの素のcompute instanceがHerokuみたいに使えるようになります（ただしDBやS3やRedisは必要に応じて別途用意する前提です。DBやRedisを合わせて別インスタンスで立ち上げる機能もあります）。37Signalsではproductionで使っているようですが、まだまだ荒削りなので、しばらくは一緒に開発したいくらいの勢いで使いたい人向けかと思います。

## MRSKとは

https://mrsk.dev/

Railsの創始者DHHが新しく作ったデプロイツールです。初コミットは2023年1月7日で、真新しいプロダクトなのですが、中身は今どきのクラウドネイティブな世界観から見ると、懐かしい感じもします。

なぜ今これが作られたかというと、37Signalsの（脱）クラウド戦略にあります。37Signalsはこれまでいろんなサービスを作ったり閉じたりしつつ、それなりの規模のサービスを運用しています。現行サービスの運用にはクラウドを多用していたのですが、最近脱クラウドを進めています。理由は、ワークロードが安定している場合は、クラウドを使わず自前の機材を使った方が安くつきそう、ということのようです。

とはいえ自前の機材では運用する基盤が欲しくなります。これまでkubernetesを利用していたりもしたのですが、自前でK8sを動かすのも大変なので、もっと手軽に運用できるツールを探し、「シンプルな奴を自分で作った方が早いのでは？」という発想で作られたのがMRSKというわけです。

クラウド離脱・移転のもろもろについてはDHHもブログで書いていますが、今回の移転作業にも協力しているDeft社のケーススタディ記事（ https://deft.com/case-study-37signals/ ）の方が分かりやすいかもしれません。クラウドの価格はさておき、自力でオンプレ運用するのは大変そうなので、脱クラウドは今ひとつ現実味がないのですが、Deft社のようなところと組めるなら実現可能なのかもしれないな、と思いました。DHHと脱クラウドとMRSKについては、laiso.hatenablog.comの記事も参考になります。

ただ、普通は脱クラウドに走るよりも、実験用環境や学習用環境、個人開発等のために安くて低機能なサーバで動かしたい、という需要の方が大きそうです。そして今どきはそんな用途でもコンテナを使いたくなります。コンテナとなるとAWS等でコストをかけて構築するか、Herokuやfly.io等のもろもろ隠蔽された便利サービスを使う場合が多いかと思いますが、そういう環境は便利な反面、あれがないとかこれが高いとかいう話になりがちでした。MRSKは、もっと手軽に格安コンテナ環境を動かしたいという、ある程度サーバの知識がある人向けのデプロイツールとしても期待できそうです。

とはいえサーバのハードを調達するのは大変なので、以下ではクラウドやVPSなどで使う前提で話を進めます。なお、当初はMRSKのバージョン0.8.4を前提にしていましたが、0.9.1に上げました。

## 必要なもの

- Linuxサーバ

- Docker Hubかなにかのアカウント

- アプリをDockerで動かすためのDockerfile

accessoriesとしてDBやredisをコンテナで立ち上げることもできますし、別途用意したサーバを使うことも可能です。私はLinodeでDBを用意してみました。RDS等を使うのもよいかと思います。

## Linuxサーバを用意する

まずsshでログインできるLinuxサーバを用意します。ディストリビューションはUbuntuかDebianが推奨で、私はDebianで試していました。

MRSKはデフォルトでは、rootでいきなりsshログインするすごい思想です。別アカウントでも利用可能ですが、若干手間がかかります。

サーバの置き場所は何でも良さそうで、AWSやAzureのインスタンスでも、DigitalOceanやLinodeでもよいでしょう。日本だとWebARENA Indigoが一番安そうで、月額349円です。これでもMRSKは動くようでした。もちろんベアメタルの自前サーバでもよいかと思います。

## その他のコマンド

その他いろいろなコマンドがあり、HerokuとかCapistranoっぽい雰囲気です。

- `mrsk details` 動いているコンテナの情報が得られます

- `mrsk app exec 'bin/rails about'` Railsのコマンドも実行できます

- `mrsk app exec -i bash` コンテナ内のシェルにログインできます

- `mrsk app exec -i 'bin/rails c'` Railsのconsoleに入れます

- `mrsk app logs` ログが見られます

- `mrsk config` 設定情報が見られます。秘密情報がそのまま表示されてびっくりします（さすがにissueが立っていました）

- `mrsk stop` アプリを止めます

- `mrsk start` アプリを起動（再開）します

- `mrsk remove` 全コンテナを消して初期状態に戻します

RailsでまっさらなDBから始めるなら、`bundle exec mrsk app exec 'bin/rails db:create db:migrate'`辺りから始めることになりそうです。

## 遭遇したトラブル

- ERROR (SSHKit::Command::Failed)が出る

サーバにdockerが入っていない場合、MRSKはsudoもつけずにいきなりapt-getしだすので、rootでないと動きません。また標準の設定では、rootでないとdockerコマンドが動かないようでした。`ssh.user`でroot以外を設定した場合は、先述のsetup.shを実行しておきましょう。

- `docker buildx build`を実行中にERROR: failed to do requestで死ぬ

詳細は不明なのですが、私の環境では何度か発生しました。ログに表示されるdockerコマンドを普通に実行してもエラーが再現したので、MRSK側の問題でもなさそうでした。これが出た場合、ローカルのDocker自体を終了＆再起動すると動いたりしました。

## おわりに

これが半年くらい前、Heroku有料化の騒ぎが起こる前に完成していれば、選択肢が増えてよかったのにな、と思いました。

ふつうにクラウドでコスト的にも満足している人には不要そうなツールですが、お金をけちりつつ自前サーバでいろいろやりたい人にとっては、そこそこ実用的で面白いツールになりそうです。実験用の格安サーバ環境としてはDBの準備が厄介なところで、DHHはSQLite推しのようでしたが、この辺はLitestreamあたりを使って解決する方が賢明なのかもしれません。

MRSK自体の完成度はまだ低そうで、良く言うと伸び代しかない状態です。それを楽しめる人は手を出してみるのも良さそうですね。私もcapistranoで運用しているRailsアプリを、MRSKに移行してみようかと思いました。
