# Tailwind CSS for Railsを使って、NodeをインストールせずにTailwind CSS 3を導入する

これはRuby on Rails Advent Calendar 2021の20日目の記事です。20日は誰も埋めていなかったので書いてみました（と言いつつ、書いているうちにもう日付が変わってしまいましたが……）。

ここではTailwind CSS for Railsというgemについて書きます。

## Tailwind CSSとRails

Tailwind CSSは最近流行のCSSフレームワークで、Utility-Firstと呼ばれている思想に基づいています。これはある意味、従来のCSS設計のベストプラクティスの真逆を行くものです。

例えば`class="flex items-baseline mt-4 mb-6 pb-6 border-b border-gray-200"`のようなスタイル指定が、直接タグに書かれることになります。長らくCSSを使いこなし、OOCSSやBEMに慣れている人こそ、このHTML内に埋め込まれた謎の記法に驚いていたようです。

とはいえ、ReactやVue等の普及でフロントエンドのコンポーネント指向が強まり、CSS自体でコンポーネントを考慮した命名規則を駆使しなくても良くなりました（RailsのViewでコンポーネントを使う場合、最近はViewComponentを使う場合が多い印象です）。またPurgeCSSなどでCSS定義のうち必要な部分のみを切り出せるようになり、巨大なUtility CSSを用意しても、本番環境でのCSSはシンプルにできるようになりました。

こういったトレンドの変化により、好き嫌いや開発現場の事情はあるにせよ、Tailwindは一定の評価を広く得られているようです。

さて、これまでRailsでTailwindを使う方法としては、

- Webpacker・Simpacker等と組み合わせてnpmでインストールする

- Next/Nuxt等を使ったフロントエンド側に任せて、Rails側では何もしない

- CDN上にあるTailwindを使う

といったやり方がありました。

一方、Rails 7ではWebアプリケーション開発の概念圧縮（Conceptual Compression）を推し進めるべく、Node.jsを使わなくてもRails自身でいろいろできるよう、新たなgemの開発が進められてきました。TailwindについてもNode.js不要で使える仕組みが期待されていたわけですが、そこに現れたのがTailwind CSS for Railsです。

## Tailwind CSS for Railsとは

https://github.com/rails/tailwindcss-rails

RailsでTailwindを扱うためのgemで、2021年1月からDHHにより開発が開始されました。v1.0.0が正式リリースされたのは日本時間では12月15日、Rails 7のリリースの前日でした。そして12月20日現在のバージョンはv2.0.2です。

……と、v1.0.0リリースの前後に大きな動きがあったので、順をおって説明します。

## v1.0.0前後の動き

Rails 7のリリースに向け、12月になった頃からTailwind CSS for Railsの開発にも動きが見えてきました。12月3日にはv0.5.4がリリースされています。Rails 7も12月7日にv7.0.0のRC1が公開されました。

そして12月10日、Tailwind CSS v3.0がリリースされます。v3.0ではv2.1で導入されたJITエンジンが標準になっており、そのため実際のところ、Node.jsがないと利用が難しいものとなっていました。

12月15日にリリースされたTailwind CSS for Rails v1.0.0は、Tailwind CSS v2.1に対応したバージョンとしてリリースされました。v3対応は今後の課題、ということになっていたわけです。この時点でTailwind CSS v3を今すぐ使いたい人は、cssbundling-railsと合わせてNode.jsを使って利用するしかない状況でした。これはRails 7のポリシー的には好ましくありませんし、それならわざわざ独立したgemにする必要もなかったのでは、ということになりかねません。

ところが12月17日、Tailwindの公式ブログでStandalone CLIがアナウンスされます。RailsやPhoenixのようなNode.jsやnpmを使わない環境でも、Tailwindの全性能が使えるよう自己完結型のCLIを用意した、という内容でした。これはびっくりしました。

Standalone CLIは、要するにTailwind CSSのJITエンジンをNode処理系ごとまとめて1個のでかいバイナリにしたものです。Rubyで言えばExerbやTraveling Rubyみたいなものに相当するでしょうか。内部でNode処理系を使っているので「普通にNode.js使ってるっしょ」と言いたくはなりますが、それでもnpmでいろいろ作業しなくて済むのは便利です。

12月18日にはこのStandalone CLIを取り込むpull requestがマージされ、その日のうちに2.0.0.rc1と2.0.0正式版がリリースされました。なお、v1.0.0にはPurgeCSSのようなことをRubyで行うPurgerがあったのですが、2.0.0では丸ごと消されています。CLIがよろしくやってくれるので、Ruby側での処理は不要になったわけです。

その後細かい修正を行い、12月20日にv2.0.1とv2.0.2が立て続けにリリースされました。今後は仕組みから考えて、Tailwind CSSのバージョンアップごとにTailwind CSS for Railsも適宜リリースされていく形になるかと思います。

## おわりに

Tailwind CSS for Railsが出てきた当初は、便利そうだけれどちょっと無理矢理感も否めないな、と感じていました。以前のRailsで使われていて廃れた、JSをgemでwrapする手法も脳裏をよぎりました。そしてTailwind CSS v3.0の登場時には一体どうなるのかと心配したのですが、Standalone CLIの登場により一気に状況が変わり、安定して使えそうなツールに生まれ変わったようです。

ところで、Standalone CLIが利用しているpkgも興味深いところです。これはVercelが提供しているツールで、READMEによれば基本的にはコンテナ内で使うためのものだそうです。Node.jsによるフロントエンドのエコシステムを牽引するVercelが、Node.js不要なエコシステム作りにも大きな影響を与えているというのは、思わぬ因縁を感じますね。
