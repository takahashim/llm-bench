## 秘密はRubyNext

動く秘密は`require "ruby-next/..."`という行にあります。これはRubyNextというライブラリを読み込むものです。

RubyNextはEvil MartiansのVladimir Dementyevが開発しているライブラリで、一言で言うとRubyのトランスパイラです。gemでインストールできます。

[コード]

Gemfileに書いて`bundle install`して使うこともできます。

RubyNextはRubyのファイルをトランスパイルして、結果を別のファイルとして保存することもできますが、それとは別に、実行時に`require`（`require_relative`も）をすげ替えて、ライブラリを書き換えつつ実行することもできます。requireをすげ替えるため、スクリプトをparseしてバイトコードにコンパイルする前にトランスパイルでき、新しいリテラルを導入できる、というわけです。

言い換えると、この技はライブラリにしないと使えません。上の例では、`sample.rb`に直接このリテラルを書くことはできません。

また、requireのすげ替えはあらゆるディレクトリに対して行われるわけではなく、標準ではlibやappやspecなど決まった名前のディレクトリに対してのみ適用されます。それ以外のディレクトリでも使えるようにするには、`RubyNext::Language.watch_dirs`を設定します。私はこの設定が分からず、同階層に置いても動かなくてしばらくハマりました。

## RubyNextの機能

RubyNextには、何をどうトランスパイルするかについていくつかの機能があります。

- 新しいバージョン用のRubyスクリプトを動かす（Ruby 2.6でRuby 2.7の新機能を使うなど）

- まだリリースされていないバージョン用のRubyスクリプトを動かす

- まだコミットされていない（提案のみの）機能を使ったRubyスクリプトを動かす

ドキュメントでは2番目がEdge features、3番目がProposed featuresと呼ばれています。ES6風Hashリテラルのために使いたいものは、このProposed featuresです。これを使えるようにするためのコードが、`sample.rb`にあった`require "ruby-next/language/proposed"`です。

RubyNext 0.10.0の時点で、Proposed featuresとして利用できるものは2つです。

- Method reference operator (`.:`)　#13581

- Shorthand Hash notation (`data = {x, y}`)　#15236

今回使っているのは後者のShorthand Hash notationですが、前者のメソッド参照演算子も使えます。

## おわりに

RubyNextがProposed featuresを導入しているのは、新しい機能を正式に導入する前に、多くの人が簡単に試せる機会を提供するためだとされています。このアプローチはJavaScriptのエコシステムを参考にしたものです。

これはRuby言語の開発でも同じようなアプローチを採用してはどうか、と思っています。「マージか取り消しか」の二者択一ではなく、トランスパイラのユーザーから広くフィードバックを集めて、それを元に機能を受け入れるプロセスがあってもよいのではないでしょうか。

> Ruby Nextは、Rubyを未来に向けて前進させるトランスパイラを目指しています

（「Ruby NextトランスパイラでRubyの新機能を使おう（翻訳）」より）

ということで、Rubyのより良い進化を促すためにも、興味のある方はRubyNextを試してみてはいかがでしょうか。
