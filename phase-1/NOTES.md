判定: `pairs/judge.md` に記入 → `python3 score.py`。合格は10本中7本以上。

## 判定の解釈で割り引くべき点

**1. URL の捏造（14件）**
事実リストに URL は無いが、候補 04/05/06/07/09/10 に Opus が自分の知識から
URL を追加した。数値の逸脱はゼロ。URL で原文と候補を見分けられるので、
判定では URL を無視して文章で判断する。「指示だけでは捏造を防げない」の実例。

**2. 01〜03 は構成の手本が few-shot にある**
01・02（アンチパターン）は手本01「神クラス」と同じ節構成
（症状／問題／原因／対処法／参考にしたい知見／例外／関連）を写している。
03（In-App Gems）は GoF 形式という既知の型。
→ 01〜03 の構成一致は手本の写しであり、構成を自力で組む力の証拠にならない。
   04〜10 の結果が few-shot の天井を示す。

**3. 事実リストに原文の節構成が残っている**
「典型的な症状として、〜」のように、原文の見出しが claim の中に入っている
（facts/01.yaml f6〜f9 など）。生成側に組織の仕方を一部伝えてしまっている。
Phase 0 の教師データとしてこの形を使うと、実運用より課題が易しくなる。

**4. 文体フィルタは撤回済み**
原文28件・候補22件で、著者の方が否定の対構文を多用していた。
humanizer-ja の指標はこの著者と AI を区別できない。SPEC.md 参照。
