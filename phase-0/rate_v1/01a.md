# Rubyのアンチパターン: Hashで何でも表現してしまう

Rubyのアンチパターンとして、Hashで何でも表現してしまうというものがあります。

# Hashで何でも表現することの問題点

Hashは非常に便利です。キーと値のペアで情報を保持できるので、様々な場面で使われることが多いと思います。しかし、Hashを使いすぎると様々な問題が生じます。

*   **コードの可読性の低下:** Hashの中身がどうなっているのか分かりにくい。特にキーの名前は覗けば分かっても、値の型が揃っていないと何を保持しているのか分かりません。
*   **コードの保守性の低下:** Hashは書き換え可能です。そのため、どこで値が変更されているのか追跡できず、影響範囲も把握しにくくなります。
    *   凍結されたHashでも、Hashの中身を再作成して渡すような構造では、コードの可読性は向上しません。Hashを使い回す場合も同様です。

# 解決策

これらの問題を解決するためには、Hashで何でも表現するのではなく、適切なクラスやStructを使うようにしましょう。

*   **クラスを使う:** 最も基本的な方法です。データのまとまりに合わせてクラスを定義し、その中でデータを保持するようにします。
*   **Structを使う:** クラスほど複雑な処理が必要ない場合、Structを使うこともできます。Structはクラスの簡略版であり、初期化時に指定された値でインスタンスを作成するためのメソッドを持っています。
    *   Structの初期化には `keyword_init` オプションを指定できるので、キーワード引数を使って初期化することもできます。

# 具体例

JSONを扱う場合などはHashを使わざるを得ない場面もありますが、それでも生Hashを直接使うのではなく、クラスで包んでメソッド経由でアクセスするようにすると、より安全に扱うことができます。

# まとめ

Hashは便利ですが、Hashを使いすぎるとコードの可読性や保守性が低下します。適切なクラスやStructを使って、データの型を明確にすることで、より安全でメンテナンスしやすいコードを書くことができます。

# 補足

RBSのunion typeやinterfaceの宣言により、将来的に型がより厳密になりそうですが、どのような型を用意すべきかを検討しておくことは無駄にはなりません。
