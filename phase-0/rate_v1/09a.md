# DHHの新しいデプロイツールMRSKを試してみた

## DHHの新しいデプロイツールMRSKを試してみた

DHHが今年1月に作り始めた、コンテナ向けのCapistranoとでも言うようなデプロイツール、MRSKを試してみました。

### MRSKとは

https://github.com/dhh/mrsk

37Signalsが脱クラウドしているという話は有名ですが、その過程で生まれたツールがMRSKです。MRSKは、Kubernetesを自前で回すのが大変だったので、より簡単なものを自作した方が早いという発想から生まれました。

https://www.the37signals.com/blog/2023/02/08/mrsk-and-the-rise-of-the-small-server/

脱クラウドの話の方はDHHのブログよりも、Deft社の事例記事の方が読みやすいかもしれません。

https://deft.co/blog/2023/02/mrsk-deploying-rails-apps-to-heroku-servers.html

### MRSKでできること

MRSKはDockerコンテナを使ったデプロイツールです。Herokuの様なサービスを、月5ドル程度の素のインスタンスで実現できます。

MRSKはRailsアプリケーションを想定していますが、他のものでも動くと思います。ただし、ヘルスチェックに応える必要があります。Rails 7.1以降であれば、最初からヘルスチェックが用意されているはずですが、それ以前の場合は、決まったパスで200を返す機能を自分で入れておく必要があります。

### MRSKを使うのに必要なもの

MRSKを使うには、

*   sshでアクセスできるLinuxサーバ (UbuntuかDebianが推奨)
*   Docker Hubなどのイメージレジストリのアカウント
*   アプリケーションのDockerfile

が必要です。サーバはAWS、Azure、DigitalOcean、Linode、ベアメタルなど、どこでも構いません。日本国内ではWebARENA Indigoが月額349円で最も安そうでした。試してみたところ、こちらでも動きました。

### MRSKの仕組み

MRSKはログを見ると分かるように、

1.  buildxを使ってローカルにイメージを作る
2.  イメージをDocker Hubなどのレジストリにpushする
3.  サーバ側でイメージをpullしてコンテナを起動する

という流れになります。

### MRSKの使い方

MRSKはデプロイ（初回のみ）と再デプロイ（2回目以降）ができます。デプロイコマンドを実行すると、config/deploy.ymlファイルが作られます。設定はこのファイルに集約されます。大文字で書かれた値は環境変数から読み込みます。.envファイルに書いておけばそちらが優先されるようです。秘匿情報については、1passwordなどのサービスに預けて.envを生成することもできますが、今のところERBでテンプレートをごりごり書く形です。

### MRSKの設定

MRSKの設定はconfig/deploy.ymlファイルに記述します。以下はその例です。

```
# config/deploy.yml
docker_image: myapp:latest
dockerfile_path: Dockerfile
deploy_command: deploy
redeploy_command: redeploy
```

### MRSKのコマンド

MRSKには以下のようなコマンドがあります。

*   `mrsk status`: 稼働中のコンテナを表示します。
*   `mrsk run rails console`: コンテナ内のRailsコンソールを実行します。
*   `mrsk run rails dbconsole`: コンテナ内のRails DBコンソールを実行します。
*   `mrsk run bash`: コンテナ内に入ります。
*   `mrsk logs <コンテナID>`: コンテナのログを表示します。
*   `mrsk stop <コンテナID>`: コンテナを停止します。
*   `mrsk start <コンテナID>`: コンテナを起動します。
*   `mrsk restart <コンテナID>`: コンテナを再起動します。
*   `mrsk destroy`: 全てのコンテナを消去して初期状態に戻します。

`mrsk deploy`コマンドはデプロイ時に使われます。`mrsk redeploy`コマンドは2回目以降のデプロイで使われ、より高速です。

### MRSKの注意点

*   MRSKはDockerを使いますので、dockerコマンドが実行できるサーバである必要があります。
*   MRSKのデフォルトではrootのままsshでログインするため、セキュリティ上の問題があるかもしれません。
*   MRSKはまだ発展途上のツールであり、不具合や改善点が多々あります。

### MRSKの使い方

MRSKを使うには、まずDockerfileを作成する必要があります。以下はRailsアプリケーションのDockerfileの例です。

```
# Dockerfile
FROM ruby:3.1

WORKDIR /app

COPY Gemfile Gemfile.lock ./
RUN bundle install

COPY . .

ENV RAILS_ENV=production

CMD ["rails", "server", "-b", "0.0.0.0"]
```

次に、`mrsk init`コマンドを実行します。

```
mrsk init
```

これでconfig/deploy.ymlが作られます。最後に、MRSKのdeployコマンドを実行します。

```
mrsk deploy
```

### MRSKの実験

MRSKを使う上で一番大変なのは、データベースサーバの用意だと思います。DHHはSQLiteを使っているようなので、Litestreamなどのツールを使うのが良いかもしれません。

https://litestream.io/

### MRSKの課題

MRSKを使う上で遭遇した課題は以下の2つです。

1.  dockerがインストールされていないサーバでは、sudoを付けずにパッケージを入れ始めるため、root以外のユーザーでは失敗する。
2.  イメージのビルド中に通信エラーで停止することがある。ログに出ているdockerコマンドを単体で実行しても再現したため、MRSK側の問題ではないかと思われる。

これらの課題は、root以外のユーザーでの実行や、Dockerの再起動で回避できるようです。

### MRSKの感想

Herokuの有料化が騒ぎになる前にこれが完成していれば、もっと便利な選択肢になったかもしれません。クラウドの費用に不満がない人には不要ですが、出費を抑えて自前のサーバで色々やりたい人には実用的で面白いツールだと思います。

MRSK自体の仕上がりはまだ低い、よく言えば伸び代だけがある状態なので、それを面白がれる人なら手を出してみると良いかもしれません。個人的にはCapistranoで回しているアプリケーションをこれに移行しようかと思っています。
