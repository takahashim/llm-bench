# tailwindcss-railsが今の形に落ち着くまで

## tailwindcss-railsが今の形に落ち着くまで

Rails 7でTailwind CSSを使いたいRuby/Rails開発者向けのメモです。

### 背景

Tailwind CSSはUtility-Firstを掲げるCSSフレームワークで、見た目の指定がそのままタグのclass属性に長々と並ぶため、これまでのCSS設計の定石とはほぼ逆を向いています。OOCSSやBEMを使いこなしてきた人ほどHTMLに埋め込まれた記法に面食らっていたようで、好き嫌いや現場の都合はあれど一定の支持は得ているのではないかと思います。

RailsでTailwind CSSを使う場合、これまではWebpackerやSimpackerと組んでnpmで入れる、フロントエンド側のフレームワークに任せてRails側は手を出さない、CDN上のものを読むといったあたりが選択肢としてありました。

### tailwindcss-railsの登場

この状況に一石を投じたのがDHH氏によるtailwindcss-rails gemでした。2021年1月に着手され、v1.0.0の正式版は日本時間で12月15日にリリースされました。その翌日となる12月16日にRails 7が公開されているので、このgemはRails 7への対応を意識して開発されたものと考えられます。

### Node.jsなしでは使えない？

ところが、12月10日にTailwind CSS v3.0がリリースされたのですが、v2.1で入ったJITエンジンが既定となり、Node.jsなしでは実際上使いにくいものになっていました。つまり、v3を今すぐ使いたければcssbundling-railsと組み合わせてNode.jsに頼るしかないという状況になってしまいます。

Rails 7はConceptual Compressionという方針を押し進めていて、Node.jsなしでもRails自身で片が付くように新しいgemの整備が進められてきました。そのため、Node.jsに頼る状態はRails 7の方針と噛み合わず、それならgemを独立させた意味がなかったのでは、という話になりかねません。

### Standalone CLIの登場

そのような状況の中、12月17日にTailwind公式がStandalone CLIを打ち出しました。これにより、RailsやPhoenixといったnpmを前提としない環境でも、性能を落とさずにTailwind CSSを使えるようになります。

https://blog.tailwindcss.com/tailwindcss-standalone-cli

このCLIは内部でpkgというVercel製のパッケージ管理ツールを使っています。Node.jsのフロントエンド文化を引っ張ってきた会社がNode.js抜きの環境づくりにも効いているのは、思いがけない巡り合わせだと感じます。

https://pkg.sh/

Standalone CLIはJITエンジンをNodeの処理系ごと1本の大きなバイナリに固めたものです。RubyのExerbやTraveling Rubyに近い。素直にNode.jsを使っているじゃないかと言いたくもなりますが、npm周りの作業が消えるのは確かに楽です。

https://exerb.org/

### tailwindcss-railsのv1.0.0

そのため12月15日のv1.0.0はTailwind CSS v2.1向けという位置づけになります。Railsのテンプレートでコンポーネントを扱う場合は、このところはViewComponentが選ばれていることが多い印象です。

https://github.com/viewcomponent/view_component

### Node.jsなしでも使えるように！

ところが12月20日の時点では、tailwindcss-railsはv2.0.2まで進んでいて、短い間に状況が大きく動いたことになります。Standalone CLIを取り込む変更が12月18日にありました。そして、同じ日に2.0.0が公開されました。v1.0.0にあった不要なCSSを削るRuby側の処理は、CLIに任せられるので丸ごと取り除かれました。

これでNode.jsなしでも安心して使えるようになりました。

### まとめ

今後は仕組みから考えて、Tailwind CSS本体の更新に追従する形でこのgemもリリースされていくと見られます。
