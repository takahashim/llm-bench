# 有名なOSS Railsアプリのapp/以下を見比べる

## Railsアプリのapp/以下を見比べてみた

Railsアプリのapp/以下は、本来はmodelsやcontrollersなどが並ぶディレクトリです。足す必要はないのですが、プロジェクトが複雑になってくると、Railsを広げる形で独自のディレクトリを作り、関係するファイルをそこへ入れることがあります。

どんなディレクトリを足すかはアプリごとに方針が異なり、その数も基準もまるで違います。

### Mastodon

Mastodonはディレクトリの数が多めですが、それぞれの受け持ちははっきりしています。

*   **policies:** 権限の有無を返すクラス（ApplicationPolicy継承）
*   **validators:** ActiveModel::Validatorを継いだ検証クラス

assetsをやめてjavascriptをapp/の直下に持ってきているなど、Railsの標準とは異なる部分もあります。app/libというディレクトリをroot側のlibと別に持ち、素朴なクラスを収めているのも特徴的です。

### rubygems.org

rubygems.orgはほぼ標準どおりの構成で、独自に足されているのはRackのミドルウェア1つを収めたディレクトリだけです。

### Redmine

Redmineはcontrollers・helpers・models・viewsの4つだけで、Rails初期の形を今も守っているようです。かえって手入れしやすいという面もあるのかもしれません。

### Diaspora

Diasporaの独自ディレクトリは、コントローラからJSONを返すためのpresenters、書き出し用途でActiveModel::Serializerを継いだserializers、素朴なクラスが入るservices、Sidekiq向けに基底クラスを継いだworkersあたりです。

### GitLab

GitLabは非常に多くのディレクトリを抱えています。モデル以外にも関わる検索処理をクラスへ出すfindersや、View関連のロジックやデータを持つpresentersもあります。これらはモデルが太るのを避ける役目を持っています。

また、Grape::Entityを継いだserializersやDeclarativePolicyのフレームワークを使った権限管理、CarrierWaveの基底を直接継がず自前のクラスを経由させているuploadersなどもあります。graphqlディレクトリがあるのは今の流行に沿っているという感じです。

### Forem

Foremはdev.toの実体で、非常に多くのディレクトリを抱えています。ファイルが1つしかないものもあります。

どんな方針でディレクトリを足しているのかはドキュメントを読んでも読み取れなかったので、独自ディレクトリを一切作らないアプリと比べてみます。

### Discourse

Discourseも素直な構成です。標準から外れているのは、モデルを直列化するクラスを収めた場所と、サービス用のクラスを置く場所くらいです。

サービス用のクラスは共通の親を持たないただのRubyのクラスで、メソッドの決まりもほとんどなく数も多いです。

### 結論

アプリごとにまったく異なる考え方があることがapp/の一階層を眺めるだけでも見えてきます。

GitLabのように独自に足したディレクトリに説明のREADME.mdを置いておく（すべてではない）のは、読む側としては非常に助かりました。この習慣は取り入れる価値があると思います。
