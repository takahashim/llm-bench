# 有名なOSS Railsアプリのapp/以下を見比べる

Railsアプリでは、app/直下に独自ディレクトリを作るかどうかはそれぞれのプロジェクト次第です。

Redmineのようにcontrollers・helpers・models・viewsだけというアプリもあれば、Foremのように大量のディレクトリを持つアプリまで様々です。MastodonやDiscourseは標準から外れており、GitLabはグラフQL用に専用のディレクトリを設けています。

ここでは有名なOSS Railsアプリのapp/以下を見比べてみます。

*   **rubygems.org:** https://github.com/rubygems/rubygems.org/tree/master/app

ほぼ標準的な構成で、追加されているのはRackミドルウェア専用のディレクトリだけです。

*   **Redmine:** https://github.com/redmine/redmine/tree/stable/app

rails初期の頃と変わらずcontrollers, helpers, models, viewsのみで運用されています。railsのapp/は本来不要なものですが、複雑になるとrailsを拡張して独自ディレクトリを作成することがあります。

*   **Mastodon:** https://github.com/tootsuite/mastodon/tree/master/app

かなり多くのディレクトリがあり、それぞれの役割は明確です。

    *   policies: ApplicationPolicy継承権限関連クラス
    *   validators: ActiveModel::Validator継承検証クラス
    *   services: BaseService継承サービスクラス
    *   app/lib: 素朴なクラス

assetsをなくしてjavascriptをapp/の直下に移動させ、libはroot側と別にapp/libを作成しています。

*   **Discourse:** https://github.com/discourse/discourse/tree/master/app

こちらも比較的シンプルで、標準から外れているのはActiveModel::Serializer継承モデルシリアライザクラス専用ディレクトリとサービス関連のクラスを置く場所のみです。

    *   serializers: ActiveModel::Serializer継承モデルシリアラライズクラス

*   **GitLab:** https://github.com/gitlab-org/gitlab/tree/master/app

非常に多くのディレクトリを持っており、ファイルが1つしかないものもあります。

    *   finders: モデル以外の検索処理を担当するクラス
    *   presenters: View関連のロジックやデータを担当するクラス
    *   graphql: グラフQL用ディレクトリ

DeclarativePolicy用フレームワークを使用し、権限管理に利用しています。serializersはGrape::Entity継承クラスを持ち、uploadersはCarrierWaveの基底クラスではなく自作のクラス経由で利用しています。

*   **Forem (dev.to):** https://github.com/forem/forem/tree/master/app

非常に多くのディレクトリがあり、どのような方針でディレクトリを追加しているかはドキュメントから読み取れませんでした。
https://github.com/codeforjapan/decidim-cfj/tree/master/app

Mastodon, Discourse, GitLabと同様に多くのディレクトリがあり、Diasporaで追加されているサービス用のクラスは共通の親クラスを持たない単純なRubyクラスであり、メソッドもほとんどなく大量にあります。
