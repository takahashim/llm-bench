# tailwindcss-railsが今の形に落ち着くまで

## tailwindcss-railsが今の形に落ち着くまで

Rails 7でTailwind CSSを使いたいRuby/Rails開発者向けに、tailwindcss-railsの歴史をまとめます。

### Tailwind CSSとは

Tailwind CSSはUtility-Firstを掲げるCSSフレームワークです。見た目を指定すると、そのままHTMLのclass属性に長々と並びます。Railsで使う場合は、WebpackerやSimpackerといったフロントエンド環境と組み合わせてnpmからインストールしたり、フロントエンド側のフレームワーク（React, Vueなど）を使って実装し、Railsはあまり関与しないことが多かったです。またはCDN上のものを読むという手もありました。

### tailwindcss-railsとは

tailwindcss-railsはDHHが2021年1月に着手したgemで、日本時間では12月15日にTailwind CSS v2.1向けのv1.0.0正式版が出て、翌日にはRails 7が公開されました。ところが12月20日の時点では、tailwindcss-railsはv2.0.2まで進んでいて、短い間に状況が大きく動きました。

### Node.jsなしでもTailwind CSSを使う

Railsのテンプレートでコンポーネントを扱う場合は、このところはViewComponentが選ばれていることが多い印象ですが、tailwindcss-railsはNode.jsなしでもTailwind.cssを使えるようにするためのgemです。というわけで12月15日のv1.0.0ではTailwind CSS v2.1向けという位置づけでした。

### Node.jsに頼る状態とRails 7のConceptual Compression

ところが12月10日に出たTailwind CSS v3.0ではv2.1で入ったJITエンジンが既定となり、Node.jsなしでは実際上使いにくいものになっていました。Rails 7はConceptual Compressionを押し進め、Node.jsなしでもRails自身で片が付くように新しいgemの整備が進められてきましたので、Node.jsに頼る状態はRailsの方針と噛み合わず、それならgemを独立させた意味がなかったのでは、という話になりかねませんでした。

### Standalone CLIの登場

そのため12月15日のv1.0.0はTailwind CSS v2.1向けという位置づけでした。ところが12月18日にCLIを取り込む変更が入り、同じ日に2.0.0が公開されました。v1.0.0にあった不要なCSSを削るRuby側の処理は、CLIに任せられるので丸ごと取り除かれました。

### Standalone CLIとは

12月17日にはTailwind公式がStandalone CLIを打ち出し、RailsやPhoenixといったnpmを前提としない環境でも、性能を落とさず使えるようにしました。これはJITエンジンをNodeの処理系ごと1本の大きなバイナリに固めたもので、RubyのExerbやTraveling Rubyに近いです。素直にNode.jsを使っているじゃないかと言いたくもなりますが、npm周りの作業が消えるのは確かに楽です。

### Standalone CLIの実体

Standalone CLIはpkgというVercel製ツールを使っています。Node.jsのフロントエンド文化を引っ張ってきた会社がNode.js抜きの環境づくりにも効いているのは、思いがけない巡り合わせだと感じました。

### Node.jsなしでもTailwind CSS v3を使う

このStandalone CLIのおかげで、Node.jsなしでもv3.0を使えるようになりました。ところで12月17日に公開されたtailwindcss-rails 2.0.0では、このStandalone CLIが使われています。

### 今後の動向

仕組みから考えて、今後はTailwind CSS本体の更新に追従する形でこのgemもリリースされていくと見られます。
