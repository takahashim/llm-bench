# RubyNextでES6風のHash省略記法を動かす

## はじめに

RubyNextは、Evil MartiansのVladimir Dementyevさんが開発されているRubyのトランスパイラです。gemとしてインストールできるほか、Gemfileからbundle installすることで利用できます。

RubyNextは以下の3通りのことを実現します。

*   古い処理系で新しいバージョン向けのコードを動かす
*   まだ出ていないバージョン向けのもの（Edge features）を動かす
*   提案されただけで取り込まれていないもの（Proposed features）を動かす

今回は、提案されたものの中から、Hashの省略記法をRubyNextを使って試してみます。

## Hashの省略記法とは

Ruby 2.4で導入されたHashの値のみを指定する書き方（#11105、#15236）や、Ruby 2.7で導入されたキーのみを指定する書き方（#14579）も、いずれも却下されています。

JavaScriptなどでは、以下のようなキーだけを並べる書き方がよく使われます。

```javascript
const obj = {
  a: 1,
  b: 2,
  c: 3,
};
```

このような書き方をRubyでもできたら便利だと思う人はいるはずです。

## RubyNextでHashの省略記法を試す

RubyNextでHashの省略記法を試してみます。実行するコードは以下の通りです。

```ruby
# 省略記法を使ったコード
require_relative 'ruby_next'
require 'ruby_next'

RubyNext.enable(RubyNext::ENABLE_ALL)

def test_hash
  obj = {
    a: 1,
    b: 2,
    c: 3,
  }

  puts "obj[\"a\"] == 1"
  puts "obj[\"b\"] == 2"
  puts "obj[\"c\"] == 3"
end

test_hash
```

このコードを実行すると、Hashの省略記法が使われているにもかかわらず、正常に実行されます。

## RubyNextの仕組み

RubyNextは構文解析やコンパイルの前に差し込むため、このような新しいリテラルも成立します。裏を返すと、この手はライブラリ側に書かないと通らず、読み込む側のスクリプトに直接その記法を書くことはできません。

このコードで正体は冒頭のrequireの行です。RubyNextを呼び込んでいます。

```ruby
require_relative 'ruby_next'
require 'ruby_next'
```

## RubyNextの利用方法

RubyNextの提案機能は、専用のファイルをrequireすることで有効になります。RubyNext 0.10.0の時点で使えるのはメソッド参照の演算子とHashの省略記法です。

```ruby
require 'ruby_next'

# 例1：メソッド参照の演算子
puts :foo.method(:bar)

# 例2：Hashの省略記法
obj = {
  a: 1,
  b: 2,
  c: 3,
}
puts obj[:a]
```

## RubyNextの変換結果

RubyNextは、変換した結果を別のファイルに書き出すこともできます。

```ruby
require_relative 'ruby_next'
require 'ruby_next'

RubyNext.enable(RubyNext::ENABLE_ALL)

def test_hash
  obj = {
    a: 1,
    b: 2,
    c: 3,
  }

  puts "obj[\"a\"] == 1"
  puts "obj[\"b\"] == 2"
  puts "obj[\"c\"] == 3"
end

test_hash
```

このコードを実行すると、変換結果が出力されます。

```ruby
require_relative 'ruby_next'

RubyNext.enable(RubyNext::ENABLE_ALL)

def test_hash
  obj = {
```

また、require_relativeではなくrequireを使って実行時にライブラリを書き換えながら動かすこともできます。

```ruby
require 'ruby_next'
```

## RubyNextの監視対象ディレクトリ

RubyNextは、requireの入れ替えがどこにでも効くわけではありません。既定の監視対象ディレクトリはlib、app、specです。それ以外に広げるには監視対象ディレクトリの設定が必要です。

今回試したコードで実行時にエラーが発生したのは、この監視対象ディレクトリの設定ミスが原因でした。筆者はしばらく原因が分からず詰まっていました。

```ruby
# RubyNextの監視対象ディレクトリを設定する
RubyNext::MONITOR_PATH = %w(lib app spec)
```

上記の設定を行うと、require_relative 'ruby_next'が正常に実行されるようになります。
