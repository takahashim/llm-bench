# Markdown 1枚からEPUBとPDFを作るCheepubを公開した

## Cheepub

Markdownのファイル1枚からEPUBやPDFを組み上げるドキュメント生成ツールを作って公開した。

設定を別ファイルに切ったり本文を分割したりせず、設定はJekyllのように文書の先頭へYAMLで書いて1枚で完結する。

完全な互換を目指すのは大変なので頑張りすぎず、手軽に実装できる範囲に留める。CLIでの使い勝手を優先しており、ブラウザで一つずつ指定するのは使う側も作る側も面倒なので、設定を文書の冒頭に書いて1ファイルで完結する形にした。

### インストール

Rubyのgemの形で配っているのでgemコマンドから入れる。

```bash
gem install cheepub
```

想定しているRubyは2.5系だが2.3あたりでも動きそう。PDFを出すにはupLaTeXかLuaLaTeXのどちらかが必要で、TeX Liveで入れるのがおすすめ。

### 使用例

Markdownの文書を用意し、必要ならメタデータと章の区切りを足して、コマンドを叩くとEPUBができる。オプションを1つ付ければPDFが出る。

```bash
cheepub my_document.md
cheepub my_document.md --pdf
```

段落にclass属性を付けるkramdown由来の拡張も使えるが、LaTeX側では右寄せだけが効く。

### 設定

オプションでタイトルや著者名、別ファイルの設定、出力ファイル名、タイトルページの有無、ページの送り方向、デバッグ用の構文木の出力などを指定できる。冒頭の設定を書かない場合はタイトルと著者名の指定が必須になる。

YAML形式で記述する。

```yaml
title: My Document
author: My Name
identifier: my_document
date: 2023-10-27
last_modified_at: 2023-10-27
page_direction: reverse
```

先頭にハイフン3つの行が来たら次の同じ行までをYAMLの設定として切り出す方式にした。設定の項目はでんでんコンバーターを手本にしようかとも考えたが複雑そうだったので、思い切って簡素なものにしてある。書けるのはタイトルと著者（どちらも省略不可）、識別子（省略時はUUIDを自動生成）、出版日と最終更新日時（省略時は現在日時で、PDFでは使われない）、ページの送り方向、奥付関連。

### Markdownの記法

Markdownの解析はkramdownで、ルビや縦中横、脚注といった記法が足されている（でんでんマークダウンに寄せたもの）。表は左右の両端に縦棒を書く形式のみで、そうでない書き方は記法がぶつかって成立しなかった。脚注はkramdown側の機能をそのまま借り、ルビはグループルビだけに対応している。

### PDFの生成

PDFの生成はLaTeXを通して行い、縦書きと2段組にはそのまま対応する。冒頭の設定に書けば済み、スタイルファイルを別に用意する必要はない。

### その他

でんでんコンバーターとの比較について。でんでんマークダウンのようなものが欲しいと思って作ったので、でんでんコンバーターとの比較が気になるかもしれない。

*   **設定**：でんでんコンバーターはYAML形式だが、YAMLの解析に失敗するとエラーになる。CheepubはYAMLの解析に失敗してもエラーメッセージを出して続行する。
*   **記法**：Markdownの記法については、でんでんコンバーターとCheepubでは異なる部分がある。
    *   kramdownを使っているのででんでんマークダウンの記法が使える。ただし、でんでんマークダウンにはないkramdown独自の記法も使える。例えば、段落にclass属性を付けるような記法だ。
    *   ルビや縦中横、脚注といった記法はkramdownの方がより多くのものに対応している。
*   **表**：でんでんマークダウンの表は左右の両端に縦棒を書く形式しか使えない。Cheepubも同じだ。
*   **タイトルページ**：でんでんコンバーターはタイトルページの出力に対応していない。Cheepubは対応している。
*   **奥付**：でんでんコンバーターは奥付の出力に対応していない。Cheepubは対応している。

### Cheepubが向いている人

目指したのはコマンドラインから使えるでんでんマークダウンのようなもので、簡単にEPUBを作りたい人向け。

### でんでんコンバーターとの使い分け

でんでんマークダウンをそのまま使いたい人にはでんでんコンバーターの方を強く勧めたい。互換性を高めるpull requestをもらっても、そこまでは手が回らないと判断して受け取らない場合があるかもしれない。

### Re:VIEWとの比較

番号付けや目次のような仕掛けがどうしても必要なら、Re:VIEWを選ぶ方がよい。

### 改ページ

改ページはイコール記号を3つ以上並べた行で表す（前後に空行を入れておく必要がある）、加えてハイフン6つ以上でも改ページになる拡張を入れた。3〜5個なら通常の区切り線として残るので書き分けられる。この決まりは後で変えるかもしれない。

### 縦中横

縦中横で使える文字をASCIIの範囲に絞っているが、この縛りは要らなかったかもしれない。

### 奥付

奥付はタイトル以外を1項目ずつ指定する形で、検討の末、項目名も含めて表を自動では作らないことにした。著者名の設定とも連動しないので別に書く必要がある。表の前後に出す文章も指定でき、版や刷の履歴と著作権の表記を想定しているが用途の制限はない。こちらは今のところMarkdownの記法が効かず、改行だけが反映される。

### その他

*   解析にkramdown、EPUBの組み立てにgepub、LaTeX経由でのPDF生成にrb_latexといったライブラリに頼っている。refinementsを使ったのでRuby 1.9では動かず、2018年なのだからもう少し新しいものを入れてほしいところ。
*   タイトルページと奥付も出せるが、EPUB側の見栄えは適当なのでもう少し手を入れたい。表紙の画像にはまだ対応していない。
