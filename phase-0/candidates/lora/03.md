# Railsアーキテクチャパターン: アプリのリポジトリ内にgemを置く

## パターン概要

ある程度まとまった機能を、アプリと一緒に管理するgemとして切り出す方法です。

### パターンの狙い

1つのclassやmoduleだけでは収まらず複数が連動する程度のまとまりを、アプリと溶け合って境界を侵さない形で持つこと。

### パターン適用例

Decidim Barcelonaはroot直下へ3つのRails Engineをgem扱いで並べている。https://github.com/decidim/barcelona

## なぜこのようなパターンが必要なのか？

Railsの融通の良さに任せると互いに依存し合う形になりやすいが、この形なら少なくともgem側がアプリ本体に頼ることは抑えられる。

## パターンの構成要素

以下は、パターン適用時の構成要素です。

*   アプリのリポジトリ
*   gemを並べるディレクトリ（root直下またはvendor/gems/）
*   gem

### ディレクトリ構成例

*   root/
    *   app/
        *   ...
    *   vendor/
        *   gems/
            *   my_app_gem/
                *   lib/
                    *   my_app\_gem.rb
                *   test/
                    *   test\_my\_app\_gem.rb
                *   Gemfile
                *   Rakefile
        *   ...
    *   ...
*   root/
    *   vendor/
        *   gems/
            *   my_app_gem/
                *   lib/
                    *   my_app\_gem.rb
                *   test/
                    *   test\_my\_app\_gem.rb
                *   Gemfile
                *   Rakefile
        *   ...
    *   my_app_engine/

## 実装手順

### 1. gemの雛形を生成する

アプリ内で以下のコマンドを実行します。

```bash
bundle gem my_app_gem
```

これにより、アプリと同じディレクトリにmy\_app\_gemというgemの雛形が生成されます。

### 2. Gemfileにgemの場所を記述する

アプリ側のGemfileに以下のような行を追加します。

```ruby
gem 'my_app_gem'
```

また、gem側のリポジトリ情報は捨て、アプリ側で一緒に管理するようにします。Decidim Barcelonaのようにroot直下に置くこともできますし、vendor/gems/ディレクトリに入れることもできます。

### 3. アプリ側からテストを書く

アプリ側ではモデルのテストでもコントローラのテストでもなく機能単位の検証をgemに付属するテストとして素直に書けるので、書き手も読み手も扱いやすい。アプリ側はリクエストやシステムの単位で書けばよい。

### 4. アプリケーション側から機能を使う

アプリケーションのコントローラなどから以下のようにしてgemを利用します。

```ruby
require 'my_app_gem'
```

## このパターンが向いている場合

*   アプリに頼らないclassやmoduleが一揃いになっていて、そのRailsアプリ以外から使う予定がなく、場合によってはいずれ取り外すかもしれないという状況。
*   ある程度まとまった機能を切り出したい（数ファイルで済むものは不要）。

## このパターンが向かない場合

*   他のアプリからも同じ機能を使いたい場合は別リポジトリを立ててGemfileに書いてそちらを参照する方が面倒が少ない。
*   アプリ専用の機能でファイル1〜2枚に収まる程度の機能なら、わざわざgemに切り出す値打ちは小さいかもしれない。
