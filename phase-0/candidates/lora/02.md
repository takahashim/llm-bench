# Rubyのアンチパターン: privateメソッドばかり増やしてしまう

## Rubyアンチパターン：privateメソッドばかり増やしてしまう

Rubyでメソッド分割したり、公開範囲を絞ったりするのは良いことです。しかし、それだけでは複雑さは減らず、むしろ増えてしまいがちです。

例えば以下のようなクラスがあったとします。

```ruby
class ReportGenerator < Struct.new(:data)
  def initialize(data)
    super data
  end

  private

  def parsed_data
    # ... some parsing logic ...
  end

  def formatted_data
    # ... formatting logic ...
  end

  def generated_report
    # ... report generation logic ...
  end
end
```

この例では`parsed_data`と`formatted_data`がそれぞれ異なる値なので、それぞれの中身に踏み込むメソッドは互いに縁が薄いように見えます。しかし、この2つのメソッドを同じクラスに入れるのは、そもそもの理由がありません。

この例の場合、以下のように分割した方が良いでしょう。

```ruby
class ReportGenerator < Struct.new(:data)
  def initialize(data)
    super data
  end

  def generate_report
    # ... report generation logic ...
  end
end

class ReportFormatter
  def format_data(data)
    # ... formatting logic ...
  end
end

class ReportParser
  def parse_data(data)
    # ... parsing logic ...
  end
end
```

このように分割した場合、`ReportGenerator`は`generate_report`のみを持ちます。残りのメソッドはすべて別のクラスに移動されました。これで問題が解決するかというと、そうではありません。
