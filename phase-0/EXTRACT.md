# 工程A: 要点リストの抽出（Phase 0 学習データ）

日本語の技術記事1本から「要点リスト」を作る。Phase -1 の粗い抽出
（`phase-1/facts_coarse/`）と同じ粒度に、**thesis（主張）** を加えたもの。

## 入力

`phase-0/texts/train/NN-*.md`。コードブロックは `[コード]` に置換済み、タイトル行なし。
タイトルは `phase-0/train_set.json` の `title`。

**`phase-1/texts/eval/` は開かない**（評価用。学習データ作成者が見てはいけない）。

## 出力

`phase-0/facts/NN.yaml`（入力ファイルの先頭2桁と同じ番号）

```yaml
source: texts/train/NN-src-id.md
title: "記事タイトル（train_set.json のまま）"
reader: "想定読者。前提知識を一言で"
thesis: "この記事を読んだ人に持ち帰ってほしいこと。1〜2文。自分の言葉で"
points:
  - id: p1
    claim: "要点。自分の言葉で"
    kind: fact | opinion | example | code
    scope: "条件があれば（例: 「Rails 7 以降」「バッチ1の場合」）"
```

## thesis の規則

- **1本に1つ。** 著者がこの記事で最も言いたいこと。要点を並べ直したものではなく、
  「だから何か」。読者が記事を閉じたあとに残るべき一文。
- 記事が主張を持たない場合（手順の記録、紹介）でも、「なぜこれを書いたか／読者は何を
  得るか」を thesis として書く。空にしない。
- 原文の言い回しを写さない（10文字以上の一致を作らない）。
- 原文に無い主張を作らない。著者が言っていないことを「主張」にしてはいけない。

## points の粒度の規則

- **10〜18件に収める。** 読者が「この記事は何を言っていたか」を人に伝えるときに挙げる
  粒度。文ごとではない。短い記事（1,000字前後）は 8〜12件でよい。
- **原文の言い回しを使わない。** 10文字以上が原文と一致する claim を書かない。
- **原文の節構成を持ち込まない。** 「典型的な症状として」「生じる問題は」「解決策は」の
  ような、記事の組み立てを示す語を claim に入れない。
- **順序を混ぜる。** id を振った後にランダムに並べ替える。原文の順番を残さない。
- 著者の判断（〜した方がよい、〜は筋が悪い）は `kind: opinion` として必ず含める。
- `[コード]` が示していたことは `kind: code` の要点として1行で。
- 留保・条件は `scope` に。箇条書きは留保を落とすので、無条件に見える claim に
  条件があるなら必ず書く。
- 原文に無いことは足さない。URL も足さない。

## 検査（抽出者が実行する）

```
python3 phase-1/check_leakage.py phase-0/texts/train/NN-*.md phase-0/facts/NN.yaml
```

5% 未満であること。超えたら言い回しを離して書き直す。

## 報告

各記事について: 要点の数、漏洩率、意図的に落とした細部を一言。
thesis の文はそのまま報告に含める（著者の検証に使う）。
