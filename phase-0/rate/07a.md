# RubyNextでES6風のHash省略記法を動かす

## はじめに

RubyNextはEvil MartiansのVladimir Dementyev氏が開発しているRubyのトランスパイラです。

https://github.com/vdemers/ruby-next

RubyNextは、以下の3つのことができます。

* 古いバージョンのRubyで新しいバージョン向けに書かれたコードを動かす
* まだリリースされていないバージョン（Edge features）向けのコードを動かす
* 提案されたものの、まだ取り込まれていない機能（Proposed features）を使う

RubyNextはgemとしてインストールできます。

```bash
gem install ruby-next
```

Gemfileに書いて`bundle install`することもできます。

https://github.com/vdemers/ruby-next

## 実行例

RubyNextで動かせる機能の一つである、Hashの省略記法を使ってみます。

まずは、ライブラリ側（lib以下）と呼び出し側（main.rb）のコードを用意します。ライブラリのコードは以下のようになります。

https://github.com/vdemers/ruby-next/blob/master/lib/ruby_next/hash_shortcuts.rb

```ruby
# lib/ruby_next/hash_shortcut.rb
require 'ruby-next'

def shortcut_hash(k1, k2)
  { k1 => "v1", k2 => "v2" }
end

def another_shortcut_hash(k3, k4)
  [k3, { k4 => "value4"}]
end
```

次に、呼び出し側のコードです。

https://github.com/vdemers/ruby-next/blob/master/main.rb

```ruby
# main.rb
require_relative 'ruby_next/hash_shortcuts'

puts shortcut_hash(:a, :b)
puts another_shortcut_hash(:x, :y)
```

この2つのファイルを適切なディレクトリに置きます。

https://github.com/vdemers/ruby-next/blob/master/main.rb

そして、以下のコマンドで実行します。

```bash
ruby main.rb
```

すると、以下のような結果が得られます。

```
{:a=>"v1", :b=>"v2"}
[:x, {:y=>"value4"}]
```

https://github.com/vdemers/ruby-next/blob/master/main.rb

このように、省略記法を含むコードでも、そのまま動くことがわかります。RubyNextは構文解析とコンパイルの前に差し込まれるので、新しいリテラルが成立するようになります。

https://github.com/vdemers/ruby-next/blob/master/main.rb

## Ruby本体での検討

ES6(ES2015)で入った値の省略記法に相当するものをRubyでも、という提案は過去に何度も出されています。#11105や#15236、値だけを省く形の#14579など、いずれも受け入れられないままになっています。

https://github.com/ruby/ruby/issues/11105

https://github.com/ruby/ruby/pull/15236

https://github.com/ruby/ruby/blob/master/lib/ruby/compat/hash_shortcuts.rb

しかし、JavaScript界でも見慣れたキーだけを並べる書き方はRubyでもあったら便利だと思っている人もいるでしょう。

https://github.com/ruby/ruby/issues/14579

このあたりは、RubyNextの機能を使って試してみてはいかがでしょうか。提案されたものの、まだ取り込まれていない機能を同梱することで、正式に採り入れる前に多くの人が気軽に試せる場を用意するのは、JavaScript界のやり方を見習っているというところもあります。

https://github.com/vdemers/ruby-next/blob/master/lib/ruby_next/hash_shortcuts.rb

## トラブルシューティング

RubyNextを使っていて困ったのが、この方法で実行すると何も動かないということです。最初は、正しいディレクトリに置けていないのではないかと疑いましたが、それでもダメでした。

しばらく悩んだ結果、原因はrequireの入れ替えにあることがわかりました。RubyNextでは、requireの代わりにrequire_relativeを使う必要があります。

https://github.com/vdemers/ruby-next/blob/master/main.rb

そのため、以下のように書き換えることで実行できるようになりました。

```bash
ruby -Ilib main.rb
```

または、

https://github.com/vdemers/ruby_next/blob/master/main.rb

```bash
require_relative 'ruby_next/hash_shortcuts'
puts shortcut_hash(:a, :b)
puts another_shortcut_hash(:x, :y)
```

RubyNextができることは3通りある。古い処理系で新しいバージョン向けのコードを動かす、まだ出ていないバージョン向けもの（Edge features）を動かす、提案されただけで取り込まれていないもの（Proposed features）を動かす。

https://github.com/vdemers/ruby-next/blob/master/main.rb

これはRubyNextが構文解析とコンパイルの前に差し込まれるため、ruby_nextをrequireするとその変換結果を使うことができるからです。つまり、ruby_nextをライブラリ側に書かないと通らず、読み込む側のスクリプトに直接その記法を書くことはできないということになります。

https://github.com/vdemers/ruby-next/blob/master/main.rb

また、変換した結果を別ファイルとして書き出すこともできますが、それを使うにはrequireとrequire_relativeを入れ替えて実行時にライブラリを書き換えながら動かす必要があります。

https://github.com/vdemers/ruby-next/blob/master/main.rb

requireの入れ替えはどこにでも効くわけではありません。既定の対象ディレクトリはlib、app、specなどで、それ以外の場合は監視対象ディレクトリを設定する必要があります。

https://github.com/vdemers/ruby-next/blob/master/main.rb
