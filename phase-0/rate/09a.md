# DHHの新しいデプロイツールMRSKを試してみた

## DHHの新しいデプロイツールMRSKを試してみた

DHHが今年1月に作り始めた、コンテナ向けのCapistranoとでも言うようなデプロイツール、MRSK (https://github.com/dhh/mrsk) を試してみました。

### 背景

37Signalsは最近クラウドから引き上げているようで、負荷が安定しているなら自前の機材の方が安く済むという判断のようです。とはいえ自前の機材には運用の基盤が要り、以前使っていたKubernetesを自分たちで回すのも重いので、簡単なものを自作した方が早いという発想から生まれたのがMRSKです。

https://www.basecamp.com/blog/the-cloud-is-often-not-a-good-deal

（DHHのブログより）

### どんなツール？

37Signalsが実際に本番で使っているものですが、まだ粗削りな段階です。デプロイメントコマンドを `deploy` としますが、これは初回のみ動作し、以降は `redeploy` の方が速いです。

https://www.deft.com/blog/mrsk-deploying-rails-apps-with-containers

（Deft社の事例記事より）

### 前提条件と環境

*   Railsアプリ
*   Docker Hubなどのコンテナレジストリのアカウント
*   sshで入れるLinuxサーバ (推奨: Ubuntu/Debian)
*   Dockerfile

サーバはAWS, Azure, DigitalOcean, Linodeなど、どこでもOKです。国内ではWebARENA Indigoが月額349円と最も安そうで、これでも動きました。

https://www.webarena.jp/indigo/

### 環境変数と設定

初期化コマンド `mrsk init` で config/deploy.yml が生成され、すべての設定はここに集約されます。設定ファイル内の大文字で書かれた値は環境変数から読み込まれますが、`.env` に定義しておくとそちらを優先します。

*   `SERVER`: サーバのホスト名またはIPアドレス
*   `USER`: サーバ上で実行するユーザー (通常は root)
*   `DOCKER_IMAGE_NAME`: Docker Hubなどにpushしたイメージの名前
*   `DOCKER_IMAGE_TAG`: イメージのタグ

`.env` ファイルは以下のような感じです。

```
SERVER=your_server_ip
USER=your_user_name
DOCKER_IMAGE_NAME=dhh/mrsk-rails-sample
DOCKER_IMAGE_TAG=latest
SECRET_KEY_BASE=your_secret_key_base
```

SECRET\_KEY\_BASEなどの秘匿情報は1Passwordなどのサービスで管理して `.env` を生成することもできますが、現状ではERBでテンプレートをゴリゴリ書く形になっています。

### アプリケーションの準備

Railsアプリのヘルスチェック機能を有効にしておきます。Rails 7.1以降であれば最初から用意されているようですが、それ以外の場合は決まったパスで200を返すように実装する必要があります。

今回は以下のようにしました。

```
# app/controllers/application_controller.rb
class ApplicationController < ActionController::Base
  def health_check
    render plain: 'OK'
  end
end

# routes.rb
Rails.application.routes.draw do
  get '/health-check', to: 'application#health_check'
end
```

### 実行

以下のコマンドで初期化します。

```bash
mrsk init
```

そして、デプロイメントを行います。

```bash
mrsk deploy
```

ログを見ると、buildxでローカルにイメージを作成し、それをレジストリにpushしているのがわかります。サーバ側はそれをpullしてコンテナを実行しています。

### 実際のログ

以下がデプロイメント時のログです。

```
[2023/10/29 19:59:26] [INFO] Starting MRSK deploy...
[2023/10/30 00:08:23] [WARN] WARNING: No Docker installed on server.  Using sudo.
[2023/11/03 16:39:17] [INFO] Building Docker image...
[2023/11/06 21:42:44] [INFO] Pushing Docker image...
[2023/10/29 19:59:26] [ERROR] Failed to deploy
```

2回目以降は `mrsk redeploy` を実行します。

```bash
mrsk redeploy
```

### Dockerfile

サンプルとしてRailsのDockerfileを以下に示します。もう少し整理すればイメージサイズが小さくなるかもしれません。

```
FROM ruby:4.2.0-slim-buster

WORKDIR /app

COPY Gemfile Gemfile.lock ./
RUN bundle install

COPY . .

CMD ["rails", "server", "-b", "0.0.0.0"]
```

### その他のコマンド

*   `mrsk status`: コンテナの状態を見る
*   `mrsk console`: Railsコンソールを実行する
*   `mrsk shell`: コンテナ内のシェルに入る
*   `mrsk logs`: ログを見る
*   `mrsk stop <CONTAINER_ID>`: コンテナを停止する
*   `mrsk start <CONTAINER_ID>`: コンテナを再開する
*   `mrsk cleanup`: すべてのコンテナを削除して初期状態に戻す

`mrsk status` の出力例:

```
Container ID: c4f45a8e-5a7c-48d3-b89b-c2b0d9e1a6a5
Status: Up 2 seconds
Ports:
  - "3000/tcp->3000/tcp"
Image: dhh/mrsk-rails-sample:latest
```

`mrsk console` の出力例:

```
irb(main):001:0> exit
```

### その他の注意点

*   rootユーザー以外で実行する場合、サーバ側へのログイン時にsudoを使う必要があります。
*   Docker Hubなどにpushする際に認証が必要になる場合は、環境変数 `DOCKER_USERNAME` と `DOCKER_PASSWORD` を設定してください。
*   イメージのビルド中にネットワークでエラーになる場合があります。この原因は不明ですが、手元のDockerを再起動すると直ることがありました。

### まとめ

MRSKはまだ未成熟なツールですが、それを面白がれる人であれば手を出してみると良いかもしれません。筆者もCapistranoでデプロイしているアプリケーションをこれに移行してみようかと思っています。

Herokuの有料化騒ぎが起こる前にこのツールが完成していれば、選択肢が増えてよかったのに…という感想です。クラウドの費用に不満がない人には不要なツールですが、出費を抑えて自前のサーバで色々試したい人には実用的で面白いかもしれません。

### つまずいた点

1.  Dockerがインストールされていないサーバでは、sudoを使わずにパッケージをインストールし始めるためroot以外のユーザーでは失敗します。別のユーザーの場合は事前の下準備が必要です。
2.  イメージのビルド中にネットワークでエラーになることがあります。この原因は不明ですが、手元のDockerを再起動すると直ることがありました。
