# Rubyのアンチパターン: Hashで何でも表現してしまう

Rubyでは、Hashを使って何でも表現してしまうアンチパターンがあります。

## アンチパターンの例と問題点

このアンチパターンは、以下のようなデータのまとまりをHashで持ち回す癖です。

```ruby
user = {
  id: 1,
  name: "Alice",
  email: "alice@example.com"
}
```

### 問題点

中身が読めない

```ruby
# user[:name] # => "Alice"
```

中身を書き換えるのも大変

```ruby
user[:email] = "alice2@example.com" # => true
user #=> {:id=>1, :name=>"Alice", :email=>"alice2@example.com"}
```

クラスやStructを使えば、より分かりやすく、中身の書き換えも容易になります。

### なぜこうなるのか？

Hashを使うのは手軽です。しかし、この手軽さのために得られるメリットよりもデメリットの方が大きくなってしまいます。

このアンチパターンは以下のような状況で起こりやすいです。

*   **よく似た別物のHashが各所を巡っている**
*   **インスタンス変数をほとんど持たずメソッドの引数のHashに情報を詰めている**
*   **1つのHashでキーの型が混ざっている (例: :id => 1, :name => "Alice")**
*   **やり取りに使うJSONを加工せず内部処理でも使っている**

### アンチパターンへの対策

このアンチパターンの根本的な原因は、データの型が不明確なことです。そこで、この問題に対処するためにクラスやStructを使ってみましょう。

#### 1. クラスを定義する

最も基本的なのは、専用のクラスを定義して使うことです。

```ruby
class User
  attr_reader :id, :name, :email

  def initialize(id:, name:, email:)
    @id = id
    @name = name
    @email = email
  end

  def to_hash # Hashとして返す必要がある場合に備えて
    { id: @id, name: @name, email: @email }
  end
end

user = User.new(id: 1, name: "Alice", email: "alice@example.com")
puts user.id #=> 1
puts user.name #=> Alice
```

#### 2. Structを使う (クラスほどでもない場合)

「ユーザー」のようなデータは、クラスを定義するほどの規模ではないかもしれません。その場合はStructを使ってみましょう。

```ruby
User = Struct.new(:id, :name, :email)

user = User.new(1, "Alice", "alice@example.com")
puts user.id #=> 1
```

この場合、`keyword_init: true` を指定するかどうかも検討してください。Structのキーワード引数は、Ruby 2.7以降で利用できます。

```ruby
User = Struct.new(:id, :name, :email, keyword_init: true)

user = User.new(id: 1, name: "Alice", email: "alice@example.com")
puts user.id #=> 1
```

#### 3. JSONを扱う場合

JSONを扱う場合は、Hashを含むオブジェクトが避けられないかもしれません。その場合でも、生のHashを使い回すのはやめましょう。代わりに、JSONを包み込むクラスを作って、そのメソッド経由でJSONにアクセスするようにしましょう。

```ruby
class User
  attr_reader :id, :name, :email

  def initialize(id:, name:, email:)
    @id = id
    @name = name
    @email = email
  end

  def to_json # JSONとして返す必要がある場合に備えて
    {
      id: @id,
      name: @name,
      email: @email
    }
  end
end

user = User.new(id: 1, name: "Alice", email: "alice@example.com")
puts user.to_json #=> {:id=>1, :name=>"Alice", :email=>"alice@example.com"}
```

### Hashを使う場合の注意点

Hashを使ってしまう場合は、以下の点に注意しましょう。

*   **キー名は分かっても値が揃っていないと何を保持しているのか読み取れない**
    *   特にRubyでは、`key: "value"` や `key => value` のようにキーを文字列とシンボルの両方で指定できるため、キーの型についての方針が定まらないことがあります。
*   **RBSのunion typeやinterfaceの宣言で型をはっきり書く将来に向けた準備としても、どんな型を用意すべきかを考えておくのは無駄にならない**

## その他の関連するアンチパターン

*   **ユーティリティクラス**：何でも詰め込むユーティリティクラスは、このようなHashを使いまわす場合と似た種類のまずい設計として挙げられます。
*   **育ちすぎたクラス**：複雑になりすぎて手に負えなくなったクラスも、同じだけ膨らんだHashよりもはるかに扱いやすいです。

## まとめ

このアンチパターンでは、Hashを使う代わりに適切な型 (クラスやStruct) を使ってみましょう。そうすることで、中身が読みやすくなり、中身の書き換えも容易になります。また、クラスがある場合は新しい処理を「その型かその周辺に足す」というように置き場所を決めることができますが、Hashには判断の起点となる型がないため処理がどこにでも散ってしまいます。

### 補足

このアンチパターンは、Hashを使うこと自体が悪いのではなく、Hashで何でも表現してしまうことが問題です。例えば、JSONを扱う場合などどうしてもHashを使わなければならない場合は、生のHashを使い回すのはやめましょう。代わりに、JSONを包み込むクラスを作って、そのメソッド経由でJSONにアクセスするようにしましょう。
